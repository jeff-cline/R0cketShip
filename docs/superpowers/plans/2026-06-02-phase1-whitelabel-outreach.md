# White-Label Automated Outreach — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every lead that enters a white-label's database is emailed that white-label's outreach offer, dripped over ≤7 days through the shared Zapmail pool, with deliverability protection, click tracking, and capacity-aware mailbox autoscaling.

**Architecture:** A new `src/outreach/` module: offer store, lead-ingest enqueue hook, deadline drip scheduler draining the queue through the existing `sendViaPool`, deliverability (verify + global suppression + bounce capture), click/unsub redirect routes, and a god capacity/autoscaling dashboard. Driven by a key-protected `/api/outreach/tick` route called by a box crontab.

**Tech Stack:** Next.js 15 App Router, Drizzle ORM + node-postgres, drizzle-kit migrations, nodemailer (via existing pool), Node `dns/promises` for MX.

### Task 1: Schema — outreach tables + settings + SendKind
**Files:** Modify `src/db/schema.ts`, `src/email/mailbox.ts` (SendKind); generate `drizzle/0020_*.sql`.
- `outreach_offers`: id, tenantId (unique FK), logoUrl, title, description, ctaUrl, active(bool default true), createdAt, updatedAt.
- `outreach_queue`: id, tenantId(FK), leadId(FK), toAddr, status enum `outreach_status`(queued|sent|skipped|suppressed|failed) default queued, scheduledFor(ts), batchDeadline(ts), clickToken(text unique), mailboxId, sentAt, error, createdAt. Unique (tenantId, leadId). Indexes on (status, scheduledFor), (tenantId).
- `email_suppression`: id, address(text), reason enum `suppression_reason`(bounce|unsubscribe|complaint|invalid), tenantId(nullable), createdAt. Unique(address).
- `mailbox_purchases`: id, provider, count(int), monthlyCost(numeric), reason, createdBy(text), createdAt.
- `tenant_integrations` += `outreachAutoBuy boolean default false`, `outreachMaxMailboxes integer default 0`.
- `emailOutbound.kind` already text; extend `SendKind` union with `"outreach"`.
- Migration: enum creates need plain `CREATE TYPE`; generated by drizzle-kit. Apply to prod via tunnel.

### Task 4: Enqueue — `src/outreach/enqueue.ts`
**Files:** Create `src/outreach/enqueue.ts`, `enqueue.test.ts`.
- `enqueueLeads(tenantId, leadIds)`: load offer (skip if none/inactive). Load those leads. For each: derive email; skip if no email / bad syntax / suppressed / no MX. Compute `batchDeadline = now + 7d`; spread `scheduledFor` evenly across `[now+1min, now+5d]` by index (so the batch finishes well inside 7d). Insert with a random `clickToken` (crypto.randomUUID). onConflictDoNothing on (tenantId, leadId) — never re-queue.
- `spreadSchedule(n, startMs, windowMs): number[]` — pure; even spacing. Unit-tested.
- [ ] TDD spreadSchedule (n=1 → [start]; n=10 → evenly spaced within window). Integration: enqueue dedups + skips suppressed/no-email.

### Task 7: Capacity + autoscale — `src/outreach/capacity.ts`, `autoscale.ts`
**Files:** Create both + `capacity.test.ts`.
- `requiredMailboxes(queued, daysLeft, perMailboxCap)` pure: `ceil(queued / daysLeft / cap)`. Unit-tested.
- `planCapacity()`: across all queued rows grouped by earliest deadline, compute platform daily demand vs `poolCapacity(platform).cap`; return `{queued, dailyCapacity, dailyDemand, deficitMailboxes}`.
- `ensureCapacity()`: if deficit>0 and `outreachAutoBuy` on and current pool < `outreachMaxMailboxes` → buy via `src/email/zapmail.ts` purchase (key-gated; if endpoint unavailable, log + alert only), import to pool, record `mailbox_purchases`. Otherwise no-op (dashboard shows recommendation).
- [ ] TDD requiredMailboxes math. ensureCapacity guarded + logged.

### Task 8: Scheduler — `src/outreach/scheduler.ts`
**Files:** Create `src/outreach/scheduler.ts`.
- `drainDue(limit=200)`: select queued rows with `scheduledFor <= now` (oldest first, capped). For each: re-check suppression; render; `sendViaPool(tenantId, msg, "outreach")`; on sent → mark sent+sentAt+mailboxId; on skipped (no capacity) → leave queued (retry next tick); on failed → mark failed+error. Return counts.
- `tick()`: `ensureCapacity()` then `drainDue()`.
- [ ] Implement; respects pool caps automatically (sendViaPool skips when no capacity).
